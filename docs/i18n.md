# Translations

Cadence speaks English, Spanish and French. English is the source language: every string in the
QML and the C++ is written in English and marked for translation, and Qt Linguist catalogs under
`src/app/translations` carry the other two languages.

## Rules

- Every user-facing string goes through `qsTr()` in QML or `tr()` in C++. Numbers and names are
  inserted with `arg()` placeholders (`qsTr("Block ends %1 · %2 left")`), never by concatenating
  pieces, so a translator can reorder them. Counts use `%n` plurals
  (`qsTr("%n pomodoro(s)", "", count)`); English plural forms live in `cadence_en.ts`.
- User content is never translated: block names, template names, activity names and playlist names
  are shown exactly as the user typed or Spotify sent them.
- Strings that QML compares against, such as block states, block kinds and pomodoro phases, stay
  English keys (`state`, `kind`, `pomodoroPhase`). Their translated labels travel next to them
  (`stateText`, `kindText`, `pomodoroPhaseText`). Never compare against a translated label.
- Dates, weekday names and number formats come from `QLocale`. The `Language` singleton sets the
  default locale to the active language, so `QLocale()` in C++ and `Qt.locale()` in QML follow it.
- Spanish is neutral Latin American with the informal "tú". French uses the formal "vous" and a
  no-break space (U+00A0) before `: ; ? !` and inside guillemets; both bundled fonts have that
  glyph, U+202F is not used.
- Core validation messages stay English in `src/core` (the library is Qt free). Each issue carries
  a stable `IssueCode` and its arguments; `TemplateEditor::issueText` words it in the UI language.
  A new issue needs a code in `template_json.hpp` and a case in `issueText`.

## Language setting

`settings.json` stores `language` as `"system"` (default), `"en"`, `"es"` or `"fr"`. With
`"system"`, `resolveLanguage` in core picks the first entry of `QLocale::system().uiLanguages()`
whose primary tag is shipped, else English. Switching in Settings installs the new `QTranslator`,
sets the default locale and calls `QQmlEngine::retranslate()`, so the running UI changes at once.
The tray menu, the template editor issues and the Spotify status are re-worded through the
`Language.changed` signal.

## Updating the catalogs

After adding or changing strings:

```bat
cmake --build --preset windows-msvc-debug --target update_translations
```

runs `lupdate` over the app and the Spotify library and refreshes `cadence_es.ts`, `cadence_fr.ts`
and the plurals in `cadence_en.ts` (with `-no-obsolete -locations none`, so vanished strings are
dropped and the files carry no line numbers). Open the `.ts` files in Qt Linguist or edit them by
hand, then build: `lrelease` compiles them into `:/i18n/cadence_<lang>.qm` as part of the normal
build.

The ctest `cadence_translations_check` runs `lupdate` itself, on scratch copies of the `.ts`
files under the build tree, and fails when any copy ends up with an `unfinished` entry or a
`vanished` or `obsolete` one. A string added, changed or removed without `update_translations`
therefore fails the check, as does a forgotten translation; the tracked catalogs are never
rewritten by it. Run it with `ctest --preset windows-msvc-debug -R translations`.

## Adding a language

1. Add the code to `shippedLanguages` in `src/core/include/cadence/core/language.hpp` and to the
   `language` validation in `settings_json.cpp`.
2. Add it to `I18N_TRANSLATED_LANGUAGES` in `src/app/CMakeLists.txt`, run `update_translations`
   and translate the new `.ts` file.
3. Add the choice to the Language section of `SettingsScreen.qml` and the language to every entry
   of `resources/quotes/quotes.json` (authors, works, `citing` and each quote).
4. Check that the bundled fonts cover its alphabet.
